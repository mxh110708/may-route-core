# May Route 核心配套开发

本页补充 May 产品边界，其他上游配置参考保留其原始技术含义。不要为了品牌统一批量替换模块、协议或许可证。

## 配套结构

桌面仓库、其 Dashboard 子模块和本核心仓库分别记录提交。当前桌面 `version.json` 固定上游 1.14.2、Go 1.26.8，`custom-version.json` 记录 May 修订 26；核心 `go.mod` 的最低版本声明不替代桌面构建工具链。

开发布局将本仓库与 `sing-box-for-desktop-custom` 放在同级。桌面构建脚本负责服务程序、应用工作进程和安装资产的具体组合，先阅读[桌面开发教程](https://github.com/mxh110708/may-route-desktop/blob/custom-main/docs/DEVELOPMENT.zh-CN.md)。

## 修改与验证

未发行的原生 XHTTP 扩展见[支持范围及验收](MAY-XHTTP.zh-CN.md)。它属于 May 客户端扩展，不能把上游 sing-box 1.14.2 或旧发行版当作已具备同样能力。

```bash
go mod verify
go test ./...
```

完整协议测试可能需要特定平台、权限或网络夹具；记录跳过原因，不能把编译通过当作所有协议实际连通。Windows 服务、IPC、安装身份或更新校验变化还需配套 desktop 的隔离生命周期验证。

仅查看配置语法可用上游文档；修改运行配置仍须由固定核心解析并做真实业务验证。核心支持一个协议不代表 Deploy 已实现它的证书、用户、更新和恢复闭环。

## 上游与发行

上游同步由维护者选定提交并审查，保留本地差异和恢复点，不自动跟随开发分支。最终 Windows 安装包从 desktop 发行，不向用户要求手工覆盖运行中的核心 EXE。

纯文档提交不改变核心版本、协议或服务身份。现有已发布构建保持原来源记录；不能用新的 README 提交伪装成已发布二进制的构建来源。
